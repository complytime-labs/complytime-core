# Tessera-Based Evidence Ingestion Design

**Date**: 2026-05-22  
**Status**: Approved  
**Branch Strategy**: Clean slate from `main` (not based on `feat/trusted-publisher-layer1`)

## Overview

Replace the current evidence ingestion model with a Tessera-based transparency log architecture. Evidence submissions are appended to an immutable, tamper-evident log verified by internal witnesses. PostgreSQL becomes a queryable cache rebuilt from the log, not the source of truth.

This design provides cryptographic proof of evidence integrity for auditors: every evidence submission has an immutable position in the log with a timestamp that cannot be backdated or altered.

## Goals

1. **Tamper-evident audit trail**: Evidence cannot be modified or deleted after submission
2. **Cryptographic verifiability**: Independent witnesses verify log integrity and evidence quality
3. **JWT-only authentication**: All evidence submission requires OIDC token (no fallback paths)
4. **Disaster recovery**: PostgreSQL can be fully rebuilt from Tessera log
5. **Kubernetes-native**: Cloud-agnostic deployment using PersistentVolumes

## Non-Goals

1. External witnesses (Phase 2 - architecture supports but not implemented initially)
2. Migration of pre-Tessera evidence (existing evidence in PostgreSQL stays as-is with `log_index=NULL`)
3. User-submitted evidence (must go through tools using on-behalf-of flow)

## Architecture Overview

### Complete Evidence Chain

Evidence flows through four layers, each stored immutably in Tessera:

```
Layer 0: Policy Declaration
  - Gemara Policy artifact (what we're complying with)
  - Submitted once, versioned if updated
  - References: framework controls (SOC 2, FedRAMP, ISO 27001)
  - Tessera: log_index=0

Layer 1: Evaluation Evidence (per-target, continuous)
  - Gemara EvaluationLog (scanner results, tests)
  - References: Policy via tessera-log-index
  - Submitted by: CI pipelines, scanners, tools
  - Tessera: log_index=1-1000

Layer 2: Enforcement Evidence (per-target, continuous)
  - Gemara EnforcementLog (policy decisions, admit/deny)
  - References: Policy via tessera-log-index
  - Submitted by: Kyverno, OPA, admission controllers
  - Tessera: log_index=1001-2000

Layer 3: Audit Synthesis (per-target, periodic)
  - Gemara AuditLog (human judgment on one target)
  - References: Policy + Evidence via tessera-log-index
  - Submitted by: AI agent (after human review)
  - Tessera: log_index=2001

System-Wide Views (derived, not stored):
  - OSCAL Assessment Results (aggregates multiple AuditLogs)
  - Generated by: AI agents on-demand
  - NOT stored in Tessera (ephemeral)
```

**Key principle**: Individual artifacts (Policy, EvaluationLog, EnforcementLog, AuditLog) are immutable evidence stored in Tessera. System-wide reports (OSCAL) are derived views generated on-demand by agents.

### Evidence Submission Flow

```
CI/CD Pipeline or K8s Service
  ↓ JWT token (OIDC from GitHub Actions / K8s ServiceAccount)
  ↓
Gateway: POST /api/ingest
  1. Verify JWT signature (JWKS discovery)
  2. Extract (issuer, sub) from claims  
  3. Validate Gemara artifact schema (Policy|EvaluationLog|EnforcementLog|AuditLog)
  4. Append to Tessera log → returns log_index
  5. Publish to NATS: {log_index, yaml, publisher_identity}
  6. Return 202 Accepted {log_index, job_id}
```

### Async Processing (Parallel)

**IngestWorker** (NATS subscriber):
- Receives: `{log_index, yaml, publisher_identity}`
- Parses YAML (Gemara library)
- Flattens to evidence rows
- INSERTs to PostgreSQL with `log_index` column
- Stores publisher identity
- Publishes evidence event to NATS

**Certifier Pipeline**:
- Schema validation
- Provenance check (source_registry or attestation_ref)
- Executor verification (engine registered)
- Publisher identity check (issuer/sub extraction)
- Writes certification result to PostgreSQL

### Witness Verification

**Witness Service** (internal Go service):
- Polls Tessera for new checkpoints (every 10 min OR 100 entries, whichever comes first)
- For each entry in checkpoint:
  - Verifies append-only property (Tessera SDK provides consistency proofs)
  - Queries PostgreSQL for certification result
  - Verifies publisher identity matches witness config (issuer/sub patterns)
- If all entries passed full certification → countersigns checkpoint
- Publishes countersignature to Tessera

### Key Properties

- **Source of Truth**: Tessera log (append-only, immutable)
- **Query Layer**: PostgreSQL (indexed cache, rebuilt from Tessera if lost)
- **Trust Signal**: Witness countersignatures on checkpoints
- **Audit Trail**: Every evidence submission has immutable `log_index`

### Storage Backends

- **Tessera**: POSIX driver on Kubernetes PersistentVolume (cloud-agnostic)
- **PostgreSQL**: Evidence, certifications, users, policies (query layer)
- **NATS**: Event bus for async processing (existing infrastructure)

### New Components

- **Tessera Appender**: Library integrated into gateway process
- **Witness Service**: New Go binary (`cmd/witness`), runs as K8s Deployment
- **JWT Verifier**: OIDC token validation (can adapt from `feat/trusted-publisher-layer1` branch)

### Artifact Types Accepted

All artifacts submitted via `POST /api/ingest` must be valid Gemara YAML:

1. **Policy** - Control catalog, framework mapping (submitted during initial setup, versioned updates)
2. **EvaluationLog** - Scanner/test results for a specific target (continuous submission)
3. **EnforcementLog** - Policy enforcement decisions for a specific target (continuous submission)
4. **AuditLog** - Human-reviewed synthesis for a specific target (periodic submission after review)

**Handler Flow**:
```go
func IngestAsyncHandler(pub IngestRawPublisher, tracker *IngestTracker, 
                        verifier *auth.JWTVerifier, appender TesseraAppender) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        // 1. Verify JWT (403 if fails)
        claims, err := verifier.Verify(r.Context(), extractBearerToken(r))
        if err != nil {
            http.Error(w, "JWT verification failed", http.StatusForbidden)
            return
        }
        
        // 2. Read YAML body
        body, err := io.ReadAll(io.LimitReader(r.Body, MaxRequestBody))
        
        // 3. Append to Tessera
        logIndex, err := appender.Add(r.Context(), body)
        if err != nil {
            http.Error(w, "evidence log unavailable", http.StatusServiceUnavailable)
            return
        }
        
        // 4. Build publisher identity
        identity := events.PublisherIdentity{
            Sub:      claims.Sub,
            Issuer:   claims.Iss,
            Type:     inferTypeFromSub(claims.Sub),
            Verified: true,
        }
        
        // 5. Publish to NATS
        jobID := generateJobID()
        tracker.Create(jobID)
        err = pub.PublishIngestRaw(jobID, logIndex, body, identity)
        
        // 6. Return 202
        httputil.WriteJSON(w, http.StatusAccepted, map[string]any{
            "log_index": logIndex,
            "job_id":    jobID,
            "status":    "pending",
        })
    }
}
```

```go
package tessera

import (
    "context"
    "github.com/transparency-dev/tessera"
    "github.com/transparency-dev/tessera/storage/posix"
)

type Client struct {
    appender *tessera.Appender
    reader   *tessera.Reader
}

func NewClient(ctx context.Context, storagePath string, opts Options) (*Client, error) {
    storage, err := posix.New(ctx, storagePath)
    if err != nil {
        return nil, fmt.Errorf("init POSIX storage: %w", err)
    }
    
    appenderOpts := tessera.NewAppendOptions().
        WithBatching(opts.CheckpointSize, opts.CheckpointSize).
        WithCheckpointInterval(opts.CheckpointTime)
    
    appender, shutdown, reader, err := tessera.NewAppender(ctx, storage, appenderOpts)
    if err != nil {
        return nil, fmt.Errorf("create appender: %w", err)
    }
    
    return &Client{
        appender: appender,
        reader:   reader,
    }, nil
}

func (c *Client) Add(ctx context.Context, entry []byte) (uint64, error) {
    future := c.appender.Add(ctx, tessera.NewEntry(entry))
    index, err := future() // blocks until sequenced
    return index, err
}

func (c *Client) Read(ctx context.Context, index uint64) ([]byte, error) {
    return c.reader.ReadEntry(ctx, index)
}
```

### Component 3: Witness Service

**Location**: `cmd/witness/main.go` (new binary)

**Responsibilities**:
- Poll Tessera for new checkpoints
- For each checkpoint entry:
  - Verify append-only property (Tessera SDK provides consistency proofs)
  - Query PostgreSQL for certification result
  - Check publisher identity against witness config
- Countersign checkpoint if all entries passed
- Publish countersignature to Tessera

**Main Loop**:
```go
func (w *Witness) Run(ctx context.Context) error {
    ticker := time.NewTicker(w.config.PollInterval)
    defer ticker.Stop()
    
    for {
        select {
        case <-ctx.Done():
            return nil
        case <-ticker.C:
            if err := w.processNewCheckpoints(ctx); err != nil {
                slog.Error("checkpoint processing failed", "error", err)
            }
        }
    }
}

func (w *Witness) processNewCheckpoints(ctx context.Context) error {
    // 1. Fetch latest checkpoint from Tessera
    checkpoint, err := w.tessera.LatestCheckpoint(ctx)
    if err != nil {
        return err
    }
    
    // 2. Skip if already verified
    if checkpoint.Index <= w.state.LastVerifiedIndex {
        return nil
    }
    
    // 3. Verify each entry in checkpoint range
    allPassed := true
    for i := w.state.LastVerifiedIndex + 1; i <= checkpoint.Index; i++ {
        if !w.verifyEntry(ctx, i) {
            allPassed = false
            break
        }
    }
    
    // 4. Countersign if all passed
    if allPassed {
        signature, err := w.signCheckpoint(checkpoint)
        if err != nil {
            return err
        }
        if err := w.tessera.PublishCountersignature(ctx, checkpoint.Hash, signature); err != nil {
            return err
        }
        w.state.LastVerifiedIndex = checkpoint.Index
        w.state.LastCheckpointHash = checkpoint.Hash
        w.saveState()
    }
    
    return nil
}

func (w *Witness) verifyEntry(ctx context.Context, logIndex uint64) bool {
    // 1. Fetch entry from Tessera
    entry, err := w.tessera.Read(ctx, logIndex)
    if err != nil {
        slog.Error("failed to read entry from Tessera", "log_index", logIndex, "error", err)
        return false
    }
    
    // 2. Parse Gemara artifact to determine type
    artifactType, err := parseGemaraType(entry)
    if err != nil {
        slog.Error("invalid Gemara artifact", "log_index", logIndex, "error", err)
        return false
    }
    
    // 3. Query PostgreSQL for certification result
    var certified bool
    var publisherIssuer, publisherSub string
    err = w.db.QueryRow(ctx, 
        `SELECT certified, publisher_issuer, submitted_by 
         FROM evidence 
         WHERE log_index = $1 
         LIMIT 1`,
        logIndex,
    ).Scan(&certified, &publisherIssuer, &publisherSub)
    
    if err != nil {
        // Entry not in PostgreSQL yet - wait for async processing
        slog.Warn("entry not yet in PostgreSQL", "log_index", logIndex)
        return false
    }
    
    // 4. Check certification passed
    if !certified {
        slog.Warn("entry failed certification", "log_index", logIndex)
        return false
    }
    
    // 5. Verify publisher identity against witness config
    if !w.isPublisherTrusted(publisherIssuer, publisherSub) {
        slog.Warn("publisher not trusted", 
            "log_index", logIndex,
            "issuer", publisherIssuer,
            "sub", publisherSub)
        return false
    }
    
    // 6. NEW: Verify reference integrity (mapping-references)
    policyRefs, err := extractPolicyReferences(entry)
    if err == nil && len(policyRefs) > 0 {
        for _, policyIndex := range policyRefs {
            if !w.verifyPolicyReference(ctx, policyIndex) {
                slog.Warn("policy reference not found or not witnessed",
                    "log_index", logIndex,
                    "policy_log_index", policyIndex)
                return false
            }
        }
    }
    
    // 7. NEW: For AuditLog, verify evidence references
    if artifactType == "AuditLog" {
        evidenceRefs, err := extractEvidenceReferences(entry)
        if err == nil && len(evidenceRefs) > 0 {
            for _, evidenceIndex := range evidenceRefs {
                if !w.verifyEvidenceReference(ctx, evidenceIndex) {
                    slog.Warn("evidence reference not found or not witnessed",
                        "log_index", logIndex,
                        "evidence_log_index", evidenceIndex)
                    return false
                }
            }
        }
        
        // 8. NEW: Verify target scoping (all evidence for same target)
        if !w.verifyTargetScoping(entry, evidenceRefs) {
            slog.Warn("AuditLog references evidence from multiple targets",
                "log_index", logIndex)
            return false
        }
    }
    
    return true
}

func (w *Witness) verifyPolicyReference(ctx context.Context, policyIndex uint64) bool {
    // Verify policy exists at claimed log_index
    policyEntry, err := w.tessera.Read(ctx, policyIndex)
    if err != nil {
        return false
    }
    
    // Verify it's actually a Policy artifact
    artifactType, err := parseGemaraType(policyEntry)
    if err != nil || artifactType != "Policy" {
        return false
    }
    
    // Verify policy is witnessed
    return w.isIndexWitnessed(policyIndex)
}

func (w *Witness) verifyEvidenceReference(ctx context.Context, evidenceIndex uint64) bool {
    // Verify evidence exists at claimed log_index
    evidenceEntry, err := w.tessera.Read(ctx, evidenceIndex)
    if err != nil {
        return false
    }
    
    // Verify it's an EvaluationLog or EnforcementLog
    artifactType, err := parseGemaraType(evidenceEntry)
    if err != nil {
        return false
    }
    if artifactType != "EvaluationLog" && artifactType != "EnforcementLog" {
        return false
    }
    
    // Verify evidence is witnessed
    return w.isIndexWitnessed(evidenceIndex)
}

func (w *Witness) verifyTargetScoping(auditLog []byte, evidenceRefs []uint64) bool {
    // Parse target from AuditLog
    auditTarget, err := parseTarget(auditLog)
    if err != nil {
        return false
    }
    
    // Verify all referenced evidence is for the same target
    for _, evidenceIndex := range evidenceRefs {
        evidenceEntry, err := w.tessera.Read(context.Background(), evidenceIndex)
        if err != nil {
            return false
        }
        evidenceTarget, err := parseTarget(evidenceEntry)
        if err != nil {
            return false
        }
        if evidenceTarget != auditTarget {
            return false
        }
    }
    
    return true
}

func (w *Witness) isPublisherTrusted(issuer, sub string) bool {
    for _, p := range w.config.TrustedPublishers {
        if p.Issuer != issuer {
            continue
        }
        matched, err := path.Match(p.Sub, sub)
        if err != nil {
            continue
        }
        if matched {
            return true
        }
    }
    return false
}
```

### Tessera Entry Format

All Gemara artifacts stored directly as Tessera entries (no wrapper):

```
Tessera Entry (raw bytes) = Gemara YAML artifact
```

This keeps the design simple - the same YAML submitted to `/api/ingest` goes directly into Tessera. The IngestWorker already knows how to parse Gemara YAML, so no additional serialization layer is needed.

### Mapping References with Tessera Log Index

All Gemara artifacts include `mapping-references` that link artifacts together. We extend this with `tessera-log-index` to create cryptographically verifiable chains:

**Policy artifact** (defines what we're complying with):
```yaml
metadata:
  type: Policy
  mapping-references:
    - id: soc2-type2-2026
      title: "SOC 2 Type 2"
      uri: "https://www.aicpa.org/soc2"
```

**EvaluationLog** (references Policy):
```yaml
metadata:
  type: EvaluationLog
  date: 2026-05-20T10:30:00Z
  mapping-references:
    - id: soc2-policy
      title: "SOC 2 Type 2"
      tessera-log-index: 0  # References Policy at log_index=0

target:
  id: production-cluster

results:
  - control-id: CC6.1  # Control defined in Policy at log_index=0
    eval-result: pass
```

**EnforcementLog** (references Policy):
```yaml

  type: EnforcementLog
  mapping-references:
```

```yaml
  type: AuditLog

  id: production-cluster  # Single target only
```

## Error Handling and Edge Cases

### Ingestion Error Cases

**1. JWT Verification Fails**
- **Cause**: Invalid signature, expired token, unknown issuer
- **Response**: `403 Forbidden {"error": "JWT verification failed"}`
- **Logging**: Log issuer/sub (but NOT the token itself) for debugging
- **Outcome**: Evidence never enters Tessera log

**2. Tessera Add() Fails**
- **Cause**: Storage unavailable, disk full, Tessera internal error
- **Response**: `503 Service Unavailable {"error": "evidence log unavailable"}`
- **Retry**: Client should retry with exponential backoff
- **Alert**: CRITICAL - ingestion is completely down
- **Outcome**: Evidence not accepted

**3. NATS Publish Fails (after Tessera succeeds)**
- **Cause**: NATS unavailable, network partition
- **Response**: `202 Accepted {"log_index": 12345, "job_id": "...", "warning": "async processing delayed"}`
- **Recovery**: Background job scans Tessera for entries without corresponding PostgreSQL records, republishes to NATS
- **Outcome**: Eventually consistent - evidence will be processed

**4. Invalid YAML (malformed Gemara)**
- **When detected**: IngestWorker (not at ingestion time)
- **Outcome**: Evidence already in Tessera (immutable), certification fails (schema certifier returns FAIL)
- **Witness behavior**: Sees failed certification, does NOT countersign checkpoint
- **Result**: Evidence in log but not certified/witnessed

### Witness Verification Edge Cases

**5. Checkpoint with Mixed Results**
- **Scenario**: Checkpoint contains 100 entries: 95 passed certification, 5 failed
- **Witness behavior**: Does NOT countersign
- **Rationale**: Checkpoint represents a batch, must be all-or-nothing for audit trail integrity
- **Next checkpoint**: May contain only passing evidence (failed evidence remains in log but unwit witnessed)

**6. Certification Still Pending**
- **Scenario**: Witness polls checkpoint, but some entries haven't been certified yet (PostgreSQL lag)
- **Witness behavior**: Wait and retry (up to `verification_timeout` = 5 minutes)
- **After timeout**: Skip checkpoint, move to next (don't block pipeline)
- **Monitoring**: Alert if checkpoints consistently timing out (indicates IngestWorker/Certifier bottleneck)

**7. Witness Service Down**
- **Impact**: Checkpoints created but no countersignatures
- **Outcome**: Evidence ingested and queryable in PostgreSQL, but not "witnessed"
- **Recovery**: When witness restarts, processes backlog of unsigned checkpoints
- **Monitoring**: Alert if checkpoints unsigned for >30 minutes

**8. PostgreSQL Lost (Disaster Recovery)**
- **Scenario**: Tessera log intact, PostgreSQL corrupted/deleted
- **Recovery Process**:
  1. Read Tessera log from index 0
  2. For each entry: parse YAML, flatten, INSERT to PostgreSQL
  3. Re-run certification pipeline
  4. Witnesses re-verify and re-sign checkpoints
- **Outcome**: Full rebuild from immutable source of truth
- **Data loss**: None (Tessera is authoritative)

### Configuration Edge Cases

**9. Publisher Not in Witness Config**
- **Scenario**: Evidence from valid JWT (authenticated) but (issuer, sub) not in witness's `trusted_publishers` config
- **Ingestion**: Succeeds (evidence in Tessera)
- **Certification**: Publisher certifier returns FAIL (identity check fails)
- **Witness**: Does NOT countersign (certification failed)
- **Outcome**: Evidence accepted but flagged as untrusted

**10. Multiple Witnesses (Future)**
- **Architecture**: Design supports multiple witnesses, not implemented in Phase 1
- **Checkpoint publishing**: Would wait for N-of-M witness policy (e.g., 2-of-3 witnesses)
- **Disagreement**: If witnesses disagree, investigate (different certification results? config drift?)
- **Phase 1**: Single internal witness, architecture ready for expansion

### Consistency Guarantees

**What's guaranteed**:
- If evidence has `log_index`, it's in Tessera (immutable, tamper-evident)
- If checkpoint is countersigned by witness, all entries passed full certification
- PostgreSQL can be fully rebuilt from Tessera (eventual consistency)
- Log indices are sequential and contiguous (Tessera guarantee)

**What's NOT guaranteed**:
- Immediate PostgreSQL availability (async via NATS, eventual consistency)
- All evidence gets certified (malformed YAML fails schema check)
- All checkpoints get countersigned (failed certifications block witness signature)

## OSCAL Assessment Results Generation

**Key principle**: OSCAL Assessment Results are **derived views**, never stored in Tessera.

### Why OSCAL is Not Stored

**OSCAL Assessment Results** are system-wide aggregations:
- Combine evidence from multiple targets
- Represent a point-in-time snapshot
- Include human interpretation and risk statements
- Can be regenerated with different scopes/periods

**Storing OSCAL would create**:
- ❌ Duplication (same data in Gemara + OSCAL formats)
- ❌ Divergence risk (evidence updates, OSCAL doesn't)
- ❌ Multiple competing "official" reports
- ❌ Interpretation becomes immutable (but interpretations change)

**Instead**: OSCAL is generated on-demand by AI agents from immutable Gemara evidence.

### Agent-Based OSCAL Generation

**Agents query Tessera evidence and generate OSCAL**:

```python
# AI Agent tool for OSCAL generation
@tool
def generate_oscal_assessment(policy_id: str, period: str, scope: str) -> str:
    """Generate OSCAL Assessment Results from Tessera evidence.
    
    Args:
        policy_id: Policy to assess (e.g., "soc2-2026")
        period: Time period (e.g., "2026-Q2", "2026-01-01:2026-06-30")
        scope: Target scope (e.g., "production", "all", "databases")
    """
    
    # 1. Query evidence from platform (PostgreSQL fast path)
    evidence = requests.get(
        f"{GATEWAY_URL}/api/evidence",
        params={
            "policy_id": policy_id,
            "start_date": parse_period_start(period),
            "end_date": parse_period_end(period),
            "target_scope": scope
        }
    ).json()
    
    # 2. Group by target
    targets = group_by_target(evidence)
    
    # 3. For each control, aggregate findings across targets
    findings = []
    for control_id in get_controls_from_policy(policy_id):
        finding = {
            "uuid": str(uuid.uuid4()),
            "title": f"Control {control_id}",
            "control-id": control_id,
            "status": determine_status(control_id, targets),
            "related-observations": []
        }
        
        # Link to AuditLogs in Tessera
        for target_id, audit_log_index in get_audit_logs(control_id, targets):
            finding["related-observations"].append({
                "observation-uuid": f"obs-{audit_log_index}",
                "description": f"AuditLog for {target_id}",
                "tessera-log-index": audit_log_index  # Reference to Tessera
            })
        
        findings.append(finding)
    
    # 4. Build OSCAL structure
    oscal = {
        "assessment-results": {
            "uuid": str(uuid.uuid4()),
            "metadata": {
                "title": f"{policy_id} Assessment - {period}",
                "published": datetime.now().isoformat()
            },
            "results": [{
                "uuid": str(uuid.uuid4()),
                "title": f"{policy_id} - {period}",
                "start": parse_period_start(period),
                "end": parse_period_end(period),
                "findings": findings
            }]
        }
    }
    
    return json.dumps(oscal, indent=2)
```

### Auditor Workflow

**Auditor uses agents to generate reports**:

```bash

curl -X POST /workbench/api/agents/invoke \
  -d '{
    "agent": "compliance-reporter",
    "tool": "generate_oscal_assessment",
    "args": {
      "policy_id": "soc2-2026",
      "period": "2026-Q2",
      "scope": "production"
    }
  }' > assessment.json

# 2. Review findings in OSCAL format
jq '.results[0].findings' assessment.json

# 3. Drill down to AuditLog in Tessera (via reference)
audit_index=$(jq -r '.results[0].findings[0].related-observations[0]["tessera-log-index"]' assessment.json)
curl /api/tessera/entry/$audit_index > audit-log.yaml

# 4. Drill down to evidence
evidence_index=$(yq '.results[0].evidence[0].tessera-log-index' audit-log.yaml)
curl /api/tessera/entry/$evidence_index > evidence.yaml

# 5. Verify cryptographic proofs
tessera verify-inclusion --index=$evidence_index
tessera verify-consistency --from=0 --to=$evidence_index

# Later: Regenerate with updated evidence (different period, scope, etc.)
curl -X POST /workbench/api/agents/invoke \
  -d '{...}' > assessment-updated.json
```

## Deployment and Operations

### Deployment Model: Single-Organization Isolation

**Each organization runs their own private Tessera log.**

```
Organization A:
├─ Tessera log (private PV in their K8s cluster)
├─ Witness service (their internal validator)
├─ Gateway (their evidence ingestion)
└─ PostgreSQL (their query layer)

Organization B:
├─ Tessera log (separate, isolated)
├─ Witness service (separate)
├─ Gateway (separate)
└─ PostgreSQL (separate)
```

**No shared log across organizations.** Evidence contains sensitive data (vulnerability scans, configuration details, policy decisions) that cannot be made public.

### What "Transparency" Means

**Transparency = Tamper-Evident + Independently Verifiable**

NOT "Public" or "Shared"

**The transparency is FOR**:
- ✅ Organization's internal compliance team
- ✅ Auditors (granted temporary access during audit engagement)
- ✅ Regulators (if legally required)
- ✅ Customers (if contractually required for vendor assessment)

**NOT FOR**:
- ❌ General public
- ❌ Competitors
- ❌ Other organizations
- ❌ Random internet

### Why Single-Org Model Breaks the Lock

Even with private logs, the locks are broken:

**Vendor lock (BROKEN)**:
- Organization controls their own Tessera log
- Can export entire log (tlog-tiles format is open)
- Can migrate to different compliance platform
- Not trapped in vendor's database

**Trust lock (BROKEN)**:
- Auditor runs independent witness
- Verifies cryptographic proofs (doesn't trust org's claims)
- Can detect tampering (consistency proofs fail if log altered)
- Math proves integrity, not vendor assurances

**Format lock (BROKEN)**:
- Gemara is open spec (anyone can produce)
- Tessera is format-agnostic (stores bytes)
- Can add OSCAL, custom formats later
- Not locked to proprietary format

**Time lock (BROKEN)**:
- Continuous evidence stream (10 min OR 100 entry checkpoints)
- Not point-in-time snapshots
- Auditor can verify any time period

**Access lock (BROKEN)**:
- Organization owns the data
- Grants access on their terms (auditor, regulator, customer)
- Revokes access when engagement ends
- Not controlled by vendor's IAM

**The "Breaking the Lock" vision is about verifiable compliance, not public compliance.** Single-org deployment provides privacy while maintaining cryptographic verifiability.

### Backup and Disaster Recovery

**Tessera Log Backup**:

```bash
# Snapshot PersistentVolume daily using Velero
velero schedule create tessera-daily \
  --schedule="0 2 * * *" \
  --include-namespaces complytime \
  --include-resources pvc \
  --selector app=tessera

# Retention: 30 days
velero schedule create tessera-daily --ttl 720h
```

**Recovery Scenarios**:

**1. Tessera PV Corrupted**
- Restore from latest snapshot (Velero restore)
- Gateway restarts, continues from last log index
- **Data loss**: Evidence submitted between snapshot and failure (bounded by backup frequency)
- **RPO**: 24 hours (daily backup)

**2. PostgreSQL Corrupted (Tessera Intact)**
- Read Tessera log from index 0
- Republish all entries to NATS
- IngestWorker rebuilds PostgreSQL
- Witnesses re-verify and re-sign checkpoints
- **Data loss**: None (Tessera is source of truth)

**3. Both Tessera and PostgreSQL Lost**
- Restore Tessera from snapshot
- Rebuild PostgreSQL from restored Tessera
- **Data loss**: Evidence submitted after last snapshot
- **RPO**: 24 hours

**Recommendation**: Snapshot Tessera PV every 6 hours (balance between RPO and storage cost)
